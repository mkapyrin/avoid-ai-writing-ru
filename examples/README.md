# Примеры: где правила срабатывают и где молчат

Здесь лежат два набора кейсов.

- `fires/` - тексты с машинными приметами. Для каждого указано, какие правила должны сработать, на каком фрагменте и с каким приоритетом.
- `must-not-fire/` - тексты, которые человек мог написать сам. Они похожи на срабатывание: в них есть «данный», «экосистема», тире, одно «зависит от ситуации». Флагов на них быть не должно. Для каждого кейса объяснено, какое правило рискует ошибиться и почему здесь оно должно промолчать.

Второй набор важнее первого. Правило, которое ловит живой текст, вредит сильнее правила, которое пропускает машинный: после пары ложных флагов автор перестаёт верить остальным.

## Откуда тексты

Все тексты составлены мейнтейнером вручную, чтобы показать правило на коротком фрагменте. Это иллюстрации. Корпуса за ними нет, частоту приёмов в AI-текстах и в человеческих не измеряют, качество скилла не доказывают. Имена, организации и цифры в них вымышлены. Цитат реальных людей в примерах нет.

Если вы нашли живой текст, на котором скилл ошибается, пришлите его через issue «Ложное срабатывание». Такие случаи потом становятся новыми кейсами в `must-not-fire/`.

## Формат кейса

```
### <id-кейса>
- profile: <профиль>
- expect: fires | clean
- rules: [id, ...]

> текст

**Ожидание:** ...
```

- `profile` - контекстный профиль из SKILL.md: `social`, `blog`, `technical-blog`, `official`, `personal`, `email-friendly`, `creative`, `casual`. Профиль меняет строгость правил, поэтому один и тот же фрагмент в разных профилях может вести себя по-разному.
- `expect` - `fires` в папке `fires/`, `clean` в папке `must-not-fire/`.
- `rules` - для `fires` это правила, которые должны сработать. Для `clean` это правила, которые рискуют сработать по ошибке.
- В кейсах `fires` блок «Ожидание» перечисляет флаги в виде `` - `id` (P0): «фрагмент» ``. Приоритеты те же, что в SKILL.md: P0 убивает доверие, P1 даёт явный AI-запах, P2 относится к стилистической полировке. Пометка `(совет)` на месте приоритета относится ко всему тексту: скилл должен дать общую рекомендацию, например переписать текст с нуля.

У академической прозы и художественной литературы отдельного строгого профиля нет. Кейсы для них проверяют оговорки внутри самих правил: термин в прямом значении, неуверенность, подкреплённую данными, приём, который автор использует один раз.

## Как записаны тире

Скилл оставляет грамматическое тире в той форме, в какой его поставил автор, и флагует только театральные тире. Тексты самого репозитория набраны без символов длинного (U+2014) и среднего (U+2013) тире: так решил мейнтейнер, и `scripts/check.sh` это проверяет. Поэтому там, где пример должен показать сам символ, он записан меткой:

- `{U+2014}` - длинное тире, em dash;
- `{U+2013}` - среднее тире, en dash.

Читайте метку как сам символ. Дефис-минус с клавиатуры `-` записан как есть.

## Домашний стиль

`styles/` содержит примеры файлов домашнего стиля (раздел «Домашний стиль» в SKILL.md). `styles/no-dash.md` запрещает тире совсем: так пишут те, кто набирает текст с обычной клавиатуры и не хочет символов, которых на ней нет.

## Как добавить кейс

1. Выберите файл по регистру или заведите новый в нужной папке.
2. Дайте кейсу короткий уникальный id в заголовке `###`.
3. Заполните `profile`, `expect`, `rules`. Используйте только id правил, которые есть в SKILL.md.
4. Для `fires` перечислите каждый флаг с цитатой. Для `clean` объясните, почему правило должно промолчать.
5. Запустите `bash scripts/check.sh`.
